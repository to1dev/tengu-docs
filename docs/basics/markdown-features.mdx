# 脚本与插件

Tengu 的扩展规划希望让用户通过 Lua、JavaScript 和原生模块组织数据、界面与操作流程。具体脚本 API、包格式、权限控制和热重载能力，应以对应版本的实现与开发文档为准。

白皮书中的 `.tengu` 包结构和生命周期是设计说明，不是所有发行版都兼容的稳定接口。

## 规划中的扩展场景

- 整理公开行情或链上事件，生成个人观察列表。
- 组合数据查询和本地分析，减少重复操作。
- 为已有模块提供自定义界面和辅助工具。
- 在测试环境中研究策略流程和执行条件。

自动交易、插件市场与权限沙箱需要单独验证。加载成功不代表代码已通过审核，也不代表交易逻辑正确。

## 加载前核对

1. 阅读源码或从可信发布者取得代码，检查它会读取哪些文件和访问哪些网络。
2. 核对适配版本、依赖、入口和卸载方式。
3. 优先使用公开地址和测试数据，不向脚本暴露真实密钥。
4. 验证取消任务、错误处理、日志输出和资源释放行为。

如果对应版本尚未实现权限隔离，应按运行本地程序的风险级别对待插件。停止界面任务不一定已经撤销外部服务中的操作，也不能撤销已确认的链上交易。

## 参与扩展开发

先查阅[源码构建与版本](../extras/manage-docs-versions.md)，在问题反馈中说明目标提交、操作系统和扩展用途。新增 API 应说明参数、返回值、错误行为和兼容范围。

完整设计背景见[白皮书](/whitepaper)。
